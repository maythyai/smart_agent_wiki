## Critical Patterns from CONTEXT.md

**Pitfall 23:** Content script cannot access page JavaScript — use window.postMessage for communication.

**Decision 1:** Use Offscreen API for Readability.js (service workers lack DOM).

**Data Flow (lines 99-139 of CONTEXT.md):**
1. Popup opens, content script extracts HTML
2. Background service worker receives message
3. Full page → Readability.parse via offscreen document
4. Selection → extract selected text/range

    Create content script that handles messages from popup/background.

    **Implementation:**
    ```typescript
    import { extractPageContent } from './extractor';
    import { extractSelection } from './selection';

    // Track if content script is ready
    let isReady = false;

    chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
      const msg = message as Message;

      switch (msg.type) {
        case 'extract-page':
          try {
            const content = extractPageContent();
            sendResponse({ success: true, data: content });
          } catch (error) {
            sendResponse({ success: false, error: String(error) });
          }
          break;

        case 'extract-selection':
          try {
            const selection = extractSelection();
            sendResponse({ success: true, data: selection });
          } catch (error) {
            sendResponse({ success: false, error: String(error) });
          }
          break;

        case 'ping':
          sendResponse({ success: true, ready: isReady });
          break;

        default:
          // Unknown message type — ignore
          break;
      }

      return true; // Keep channel open for async response
    });

    // Notify background that content script is ready
    isReady = true;
    chrome.runtime.sendMessage({ type: 'content-ready' });
    ```

    Per Pitfall 23: Don't try to access page JavaScript variables directly.

    Implement offscreen document for DOM parsing following CONTEXT.md Decision 1.

    **offscreen.html:**
    - Minimal HTML with single script tag loading offscreen.js
    - No visible UI — purely for DOM access

    **offscreen.ts:**
    - Listen for 'parse-readability' message
    - Call parseWithReadability from readability.ts
    - Return parsed article to sender

    **readability.ts — Core parsing logic:**
    ```typescript
    import { Readability } from '@mozilla/readability';

    export interface ParsedArticle {
      title: string;
      content: string;        // Cleaned HTML
      textContent: string;    // Plain text
      excerpt: string;        // Summary
      byline?: string;        // Author
      siteName?: string;
      publishedTime?: string;
    }

    export function parseWithReadability(html: string, url: string): ParsedArticle | null {
      // Use JSDOM for DOM parsing in offscreen context
      const doc = new DOMParser().parseFromString(html, 'text/html');

      // Clone document for Readability (it modifies DOM)
      const documentClone = doc.cloneNode(true) as Document;

      const reader = new Readability(documentClone, {
        charThreshold: 500,      // Minimum chars for content detection
        debug: false,
      });

      const article = reader.parse();

      if (!article) {
        return null;
      }

      return {
        title: article.title,
        content: article.content,
        textContent: article.textContent,
        excerpt: article.excerpt,
        byline: article.byline,
        siteName: article.siteName,
        publishedTime: article.publishedTime,
      };
    }
    ```

    **Note:** Service workers don't have DOM. This offscreen document provides the DOM environment Readability needs.

  <action>
    Add Clipper class to background that orchestrates content extraction.

    **clipper.ts exports:**
    - `Clipper` class with `clipPage()` and `clipSelection()` methods
    - `createOffscreenDocument()` helper
    - `parseWithOffscreen(html: string, url: string)` function

    **Implementation:**
    ```typescript
    export class Clipper {
      constructor(private storage: StorageManager) {}

      async clipPage(tabId: number): Promise<ClippedContent> {
        // 1. Get HTML from content script
        const pageHtml = await this.getPageHtml(tabId);

        // 2. Parse with Readability via offscreen document
        const article = await this.parseWithOffscreen(pageHtml.html, pageHtml.url);

        // 3. Build ClippedContent
        return {
          url: pageHtml.url,
          title: article?.title || pageHtml.title,
          content: article?.content || pageHtml.html,
          textContent: article?.textContent || '',
          excerpt: article?.excerpt || '',
          tags: [],
          notes: '',
          source: 'chrome-extension',
          clippedAt: new Date().toISOString(),
        };
      }

      private async parseWithOffscreen(html: string, url: string): Promise<ParsedArticle | null> {
        // Check if offscreen document exists
        const contexts = await chrome.runtime.getContexts({
          contextTypes: [chrome.runtime.ContextType.OFFSCREEN_DOCUMENT],
        });

        if (contexts.length === 0) {
          await chrome.offscreen.createDocument({
            url: 'offscreen/offscreen.html',
            reasons: [chrome.offscreen.Reason.DOM_PARSER],
            justification: 'Parse HTML with Readability.js for content extraction',
          });
        }

        // Send message to offscreen document
        const response = await chrome.runtime.sendMessage({
          type: 'parse-readability',
          html,
          url,
        });

        return response;
      }
    }
    ```

    Per Pitfall 22: This stateless operation — no need to persist offscreen instances.

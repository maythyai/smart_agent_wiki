# Plan 03: Query Engine -- Search + Context Compilation + NL Query + Graph

<objective>
Build the complete query engine: BM25+FTS5 keyword search, Tree Mode structured search,
context compilation with token budget, natural language query via LLM with layered answers
and inline citations, graph traversal (BFS/DFS), and comparison analysis. Wire to `saw query`
and `saw search` CLI commands.

Purpose: This is the "read" half of the core data cycle. Users ask questions and get
sourced answers. Every answer traces back to claims and their Vault sources.

Output: `saw search "keywords"` returns FTS5 results. `saw query "question"` returns
a layered LLM answer with `[^claim:uuid]` citations. The 5-minute onboarding promise
(init -> ingest -> query) is fully realized.
</objective>

**1. Create Search Service** in `src/saw/engines/query/search.py` (per D-13):

`SearchResult` dataclass: `claim_uuids: list[str]`, `titles: list[str]`, `contents: list[str]`, `scores: list[float]`, `total: int`

`FTS5Search`:
- `__init__(self, conn)`: store SQLite connection
- `search(query: str, limit: int = 10, offset: int = 0) -> SearchResult`:
  - Execute FTS5 MATCH query with bm25() ranking:
  ```sql
  SELECT uuid, title, content, tags, bm25(fts_index) as rank
  FROM fts_index
  WHERE fts_index MATCH ?
  ORDER BY rank
  LIMIT ? OFFSET ?
  ```
  - Return ranked results with scores
- `search_with_snippets(query: str, limit: int = 10) -> SearchResult`:
  - Same as search but include `snippet(fts_index, 0, '>>>', '<<<', '...', 32)` for highlighted context
  - Also include `highlight(fts_index, 0, '**', '**')` for bold matching
- `count(query: str) -> int`: total matching results for pagination

Note: rank-bm25 library is available for supplementary scoring but FTS5's built-in bm25() is the primary ranker. The hybrid approach is: use FTS5 bm25() for ranking, use rank-bm25 only if a separate BM25 re-scoring pass is needed (Phase 2 enhancement).

**2. Create Tree Mode Search** in `src/saw/engines/query/tree_mode.py` (per D-13):

`TreeModeSearch`:
- `__init__(self, wiki_repo, claims_repo)`: inject repositories
- `search(query: str, limit: int = 10) -> list[dict]`:
  1. Anchor retrieval: FTS5 search for query -> find matching sections in documents
  2. For each anchor, load the parent document's heading hierarchy from Wiki page metadata
  3. Tree walk: from anchor heading, walk up to parent headings and down to child headings
  4. Path aggregation: collect all claims along the path (parent -> anchor -> children)
  5. Return results with section paths like "3.2 > 3.2.1 > Finding"
- This only works for documents with heading structure (parsed by markdown-it-py in Plan 02)
- For flat documents, fall back to regular search

`SectionPath` dataclass: `path: list[str]`, `claims: list[Claim]`, `relevance_score: float`

**3. Create Graph Traversal** in `src/saw/engines/query/graph_traverse.py` (per D-16):

`GraphTraverse`:
- `__init__(self, conn)`:
  - Load entity_relation table into NetworkX graph on init
  - `self._graph = nx.DiGraph()` (per D-16)
- `_load_graph(self)`: query all entity_relation rows, add edges with weights
- `traverse(entity_name: str, mode: str = "bfs", max_depth: int = 3, max_nodes: int = 50) -> dict`:
  - Find entity by name (or alias) in entity table
  - BFS: `nx.bfs_tree(self._graph, entity_uuid, depth_limit=max_depth)`
  - DFS: `nx.dfs_tree(self._graph, entity_uuid, depth_limit=max_depth)`
  - Collect all nodes and edges within depth limit
  - Return `{nodes: list[Entity], edges: list[EntityRelation], paths: list[list[str]]}`
- `find_path(from_entity: str, to_entity: str) -> list[str]`:
  - Find shortest path between two entities via `nx.shortest_path()`
- `get_neighbors(entity_name: str, depth: int = 1) -> list[Entity]`:
  - Get directly connected entities (depth=1) or multi-hop neighbors
- `_reload_if_stale(self)`: reload graph from DB if relation count has changed

Use NetworkX 3.6.1 for all graph operations. The graph is loaded into memory from SQLite
(per D-16: "lightweight graph storage as JSONL edges" stored in entity_relation table).

**4. Create Comparison Analysis** in `src/saw/engines/query/compare.py` (per D-07 QUER-07):

`CompareEngine`:
- `__init__(self, claims_repo, wiki_repo)`: inject repositories
- `compare(page_names: list[str]) -> ComparisonResult`:
  1. Load all Wiki pages by name/path
  2. Extract claims for each page from Claims DB (by entity associations)
  3. Find shared entities/claims (intersection)
  4. Find unique claims per page (difference)
  5. Calculate similarity score: `shared_claims / total_unique_claims`
  6. Return `ComparisonResult`: shared, unique_per_page, similarity_score, summary_points

`ComparisonResult` dataclass: `pages: list[str]`, `shared_claims: list[Claim]`, `unique_claims: dict[str, list[Claim]]`, `similarity: float`

**1. Create Context Compiler** in `src/saw/engines/query/compiler.py` (per D-14):

`CompiledContext` dataclass: `content: str`, `token_count: int`, `sources: list[dict]`, `coverage: float`

`ContextCompiler`:
- `__init__(self, claims_repo, wiki_repo, search_service)`:
- `compile(question: str, token_budget: int = 4000) -> CompiledContext`:
  1. **L0 always-loaded index** (~85 lines): load wiki page titles + types + tags as overview
  2. **Search**: run FTS5 search for question keywords -> candidate claims
  3. **Graph expand**: for top entities in claims, load related entities (1-hop)
  4. **Prioritize**: sort claims by (confidence desc, relevance desc, freshness desc)
  5. **Token budget filter**: add claims to context until token count approaches budget
     - Estimate tokens: `len(text) / 4` (rough char-to-token ratio)
     - Always include claim UUID and source_uuid for citation
  6. **Format**: assemble as structured text:
     ```
     == Wiki Index (L0) ==
     [page titles and types]

     == Relevant Claims ==
     [Claim UUID: xxx] [Source: vault/xxx | p.5 | line 12]
     [Confidence: single_source] [Tags: machine-learning, transformers]
     Claim content here...

     == Related Entities ==
     Entity1 -> relation -> Entity2
     ```
  7. Return CompiledContext with coverage metric = `len(included_claims) / len(candidate_claims)`

**2. Create Query Engine** in `src/saw/engines/query/engine.py` (per D-15):

`QueryResult` dataclass:
- `answer: str` (the main answer text)
- `layered_answer: dict` (L1: title, L2: summary, L3: conclusions, L4: full detail)
- `sources: list[dict]` (each with claim_uuid, content, confidence, vault_uuid, page_number)
- `related_pages: list[str]`
- `coverage: float` (what fraction of relevant claims were included in context)
- `mode: str` (search/query/graph/compare)
- `meta: dict` (model, tokens, cost estimates)

`QueryEngine`:
- `__init__(self, search: FTS5Search, compiler: ContextCompiler, graph: GraphTraverse, compare_engine: CompareEngine, tree_mode: TreeModeSearch, llm: LLMRouter | None, claims_repo)`:
  - Inject all dependencies via protocol interfaces
- `query(question: str, depth: int = 3, mode: str = "auto") -> QueryResult`:
  1. If mode == "auto" and LLM available -> NL query path
  2. If mode == "auto" and no LLM -> keyword search path
  3. If mode == "search" -> keyword search only
  4. If mode == "graph" -> graph traversal
  5. If mode == "compare" -> comparison analysis

**NL Query Path** (per D-15):
1. `compiler.compile(question)` -> CompiledContext with token budget
2. Load system prompt from `query_default.yaml`
3. Build messages:
   ```
   system: {prompt}
   user: Context:
   {compiled_context.content}

   Question: {question}
   ```
4. `llm.answer_query(context, question)` -> raw LLM response
5. Parse response into layered answer:
   - L1: First line or heading
   - L2: First paragraph (summary)
   - L3: Key conclusions (bulleted)
   - L4: Full text
6. Extract `[^claim:uuid]` citations from answer text
7. Resolve citations to source details: for each claim_uuid, look up Claim in Claims DB,
   then look up Vault metadata via source_uuid
8. Build sources list with: claim_uuid, content excerpt, confidence level, vault document path, page number, line number
9. Return QueryResult with all assembled data

**Keyword Search Path**:
1. `search.search(question)` -> SearchResult
2. Format results as QueryResult with mode="search"
3. Include snippet context in sources

**Graph Path**:
1. Extract entity names from question (simple: split by spaces, look up in entity table)
2. `graph.traverse(entity_name, mode="bfs", max_depth=3)` -> graph data
3. Format as QueryResult with entity relationships listed

**Compare Path**:
1. Parse page names from question (comma-separated)
2. `compare_engine.compare(page_names)` -> ComparisonResult
3. If LLM available: ask LLM to synthesize comparison from data
4. Format as QueryResult

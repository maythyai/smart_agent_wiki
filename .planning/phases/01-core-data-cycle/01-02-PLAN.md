# Plan 02: Ingestion Engine -- Document Parsing + LLM Extraction + Git Provenance

<objective>
Build the complete ingestion pipeline: format detection, document parsing (Markdown/PDF/URL/code),
LLM-based claim extraction, claim fusion, validation, Write Queue integration, and Git session branch
provenance. Wire it all to `saw ingest` CLI command.

Purpose: This is the "write" half of the core data cycle. Users add documents and the system
produces structured claims, entity Wiki drafts, graph updates, and FTS5 index entries --
all flowing through the Write Queue for crash safety.

Output: `saw ingest <source>` works for Markdown files, PDFs, URLs, and code files. Each
ingestion produces verifiable claims with source provenance in the Claims DB.

> **Note on INGE-05:** INGE-05 (2 independent LLMs for cross-validation) is deferred per D-10
> (single LLM in Phase 1). Multi-LLM competition is planned for Phase 2 when the confidence
> system exists to evaluate cross-validation quality. This plan implements single-LLM extraction
> via LiteLLM with configurable model, which is the foundation for multi-LLM in Phase 2.
</objective>

```python
class PDFParser:
    def parse(self, file_path: Path) -> dict:
        """3-tier fallback: Docling -> PyMuPDF. Quality metrics on every parse."""
        # Tier 1: Try Docling
        try:
            result = self._parse_docling(file_path)
            if self._quality_check(result, file_path):
                result["parser"] = "docling"
                return result
        except ImportError:
            pass  # Docling not installed, fall through
        except Exception:
            pass  # Docling failed, fall through

        # Tier 2: PyMuPDF (always available as fallback)
        result = self._parse_pymupdf(file_path)
        result["parser"] = "pymupdf"
        return result
```

Quality validation (per Pitfall 8):
- `_quality_check(result, file_path) -> bool`:
  - Expected word count heuristic: page_count * 250 (average words per page)
  - If extracted word count < 50% of expected -> return False (quality too low)
  - Always record quality metrics in result: `{word_count, char_count, paragraph_count}`

`src/saw/adapters/parsers/html_parser.py` -- `HTMLParser`:
- `parse(url: str) -> dict`: use `trafilatura.fetch_url(url)` then `trafilatura.extract(downloaded, include_links=True, include_tables=True)` (per RESEARCH.md verified code example)
- Return: `{url, content, title, format: "html"}`

**2. Create Fuser** in `src/saw/engines/ingest/fuser.py`:

`Fuser`:
- `fuse(new_claims: list[Claim], existing_claims: list[Claim]) -> FusedResult`:
  - Compare new claims against existing claims by `content_hash`
  - Exact duplicates (same hash) -> skip
  - New claims -> mark for insert
  - Contradictions (same source_uuid, different content) -> flag for review (Phase 2 governance)
  - Return `{to_insert: list[Claim], to_skip: list[Claim], contradictions: list[tuple[Claim, Claim]]}`

**3. Create Validator** in `src/saw/engines/ingest/validator.py`:

`Validator`:
- `validate(claims: list[Claim], entities: list[Entity], relations: list[EntityRelation]) -> ValidationResult`:

  - Validate required fields: claim.content non-empty, claim.source_uuid present
  - Validate entities: name non-empty, entity_type present
  - Validate relations: source_uuid and target_uuid reference valid entities
  - Return `{valid_claims, valid_entities, valid_relations, errors: list[str]}`

**4. Create Ingest Pipeline** in `src/saw/engines/ingest/pipeline.py` (per D-12):

`ExtractionResult` dataclass: `claims: list[Claim]`, `entities: list[Entity]`, `relations: list[EntityRelation]`, `metadata: dict`

`IngestPipeline`:
- `__init__(self, claims_repo: ClaimsRepository, write_queue: WriteQueue, llm_router: LLMRouter | None, vault_repo: VaultRepository, wiki_repo: WikiRepository)`:
  - Inject all dependencies via protocol interfaces (hexagonal architecture)
  - Create extractors based on availability: `MarkdownExtractor`, `PDFExtractor`, `URLExtractor`, `CodeASTExtractor`
- `ingest(source: str, options: dict | None = None) -> IngestResult`:
  1. `classify(source)` -> determine format
  2. Route to appropriate extractor based on format
  3. `extractor.extract(source)` -> ExtractionResult
  4. `fuse(new_claims, existing_claims)` -> FusedResult (dedup against existing DB)
  5. `validate(fused_result.to_insert, entities, relations)` -> ValidationResult
  6. Generate UUID for this ingestion session: `session_id = uuid4()`
  7. Build WriteOp list for all sinks:
     - Vault: store original document
     - Claims: insert validated claims
     - Wiki: write entity draft pages
     - FTS5: update search index with new content
     - Graph: insert entities and relations
  8. `write_queue.enqueue_atomic(ops)` -- single atomic entry point per D-04
  9. Return `IngestResult(session_id, claim_count, entity_count, errors)`

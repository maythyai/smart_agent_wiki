# Plan 01: Foundation -- Domain + Write Queue + Storage + CLI Init

<objective>
Establish the entire foundation layer that Plan 02 (Ingest) and Plan 03 (Query) depend on:
domain models and protocols, Write Queue with all sinks, four-layer storage adapters,
SQLite connection with WAL+PRAGMA, configuration system, three-tier degradation detection,
agent compatibility layer, and CLI `init`/`status` commands.

Purpose: This is the bedrock. Every subsequent engine writes through the Write Queue,
queries through the Claims DB, and reads from the FTS5 index. If this layer is solid,
Plans 02 and 03 are pure engine logic.

Output: A pip-installable package where `saw init` creates a working wiki with all
storage layers, and `saw status` reports its state. Write Queue is fully functional
with crash recovery semantics.
</objective>

**1. Create Write Queue** in `src/saw/write_queue/queue.py`:

`WriteOp` dataclass:
- `op_id: str` (UUID, for deduplication per Pitfall 7)
- `session_id: str` (groups related writes)
- `sink_name: str` ("vault" | "claims" | "wiki" | "fts5" | "graph")

Outbox table DDL:
```sql
CREATE TABLE IF NOT EXISTS write_outbox (
    op_id TEXT PRIMARY KEY,
    session_id TEXT NOT NULL,
    sink_name TEXT NOT NULL,
    payload TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending',
    retry_count INTEGER NOT NULL DEFAULT 0,
    max_retries INTEGER NOT NULL DEFAULT 3,
    error_message TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT,
    UNIQUE(op_id)
);

-- Per-sink completion tracking (per Pitfall 7 recommendation 1)
CREATE TABLE IF NOT EXISTS sink_tracking (
    op_id TEXT NOT NULL,
    sink_name TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending',
    completed_at TEXT,
    error_message TEXT,
    PRIMARY KEY (op_id, sink_name)
);

CREATE INDEX IF NOT EXISTS idx_outbox_status ON write_outbox(status);
CREATE INDEX IF NOT EXISTS idx_outbox_session ON write_outbox(session_id);
```

`SQLiteWriteQueue` implementing `WriteQueue` protocol:
- `__init__(self, conn)`: create tables if not exist
- `enqueue(ops: list[WriteOp])`: atomic INSERT all ops in single transaction. All-or-nothing. Per D-04.
- `enqueue_atomic(ops: list[WriteOp])`: enqueue then immediately call dispatcher.dispatch_pending()
- `get_pending() -> list[WriteOp]`: SELECT where status IN ('pending', 'failed') AND retry_count < max_retries
- `mark_processing(op_id: str)`: UPDATE status='processing', updated_at=now
- `mark_done(op_id: str)`: UPDATE status='done', updated_at=now
- `mark_failed(op_id: str, error: str)`: UPDATE status='failed', retry_count+=1, error_message=error, updated_at=now
- `track_sink(op_id: str, sink_name: str, status: str, error: str | None = None)`: INSERT/UPDATE sink_tracking
- `get_sink_status(op_id: str) -> dict[str, str]`: return per-sink completion status

**2. Create Dispatcher** in `src/saw/write_queue/dispatcher.py`:

`Dispatcher`:
- `__init__(self, queue: WriteQueue, sinks: list[Sink])`: register sinks by name
- `register_sink(sink: Sink)`: add to sink registry
- `dispatch_pending()`: get pending ops, for each op:
  1. Mark PROCESSING
  2. Find matching sink by `sink_name`
  3. Call `sink.write(op)` in try/except
  4. On success: track_sink DONE, check if all sinks for this session complete -> mark_done
  5. On failure: track_sink FAILED, mark_failed with error message
  6. Retry logic: if retry_count < max_retries (3), status goes back to 'pending' for next dispatch cycle
- `recover()`: scan for ops in PROCESSING state (crash recovery per Pitfall 7):
  - Reset PROCESSING ops back to PENDING for re-dispatch
  - Sinks are idempotent (op_id dedup) so re-dispatch is safe

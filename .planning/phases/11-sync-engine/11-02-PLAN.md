    1. `RetryConfig` dataclass:
       - `max_retries: int = 5`
       - `base_delay_seconds: float = 1.0`
       - `max_delay_seconds: float = 16.0`
       - `exponential_base: float = 2.0`
       - `jitter: bool = True` (add random jitter to prevent thundering herd)

    2. `RetryResult` dataclass:
       - `success: bool`
       - `attempts: int`
       - `total_delay_seconds: float`
       - `last_error: Exception | None`
       - `transient_error_count: int`
       - `permanent_error_count: int`

    3. `TransientError` exception class:
       - For errors that should be retried (rate limits, timeouts, 5xx)
       - Include `retry_after: float | None` for Retry-After header

    4. `PermanentError` exception class:
       - For errors that should not be retried (auth failures, 4xx)

    5. `RetryHandler` class:
       - `__init__(self, config: RetryConfig | None = None)`
       - `def _calculate_delay(self, attempt: int) -> float`
         - Exponential: base_delay * (exponential_base ** attempt)
         - Cap at max_delay
         - Add jitter if enabled
       - `def _is_transient(self, error: Exception) -> bool`
         - Transient: HTTP 429, 500, 502, 503, 504, timeouts, connection errors
         - Permanent: HTTP 401, 403, 404, 400
       - `async def execute(self, func: Callable[..., Awaitable[T]], *args, **kwargs) -> RetryResult`
         - Execute async function with retry logic
         - On TransientError: wait and retry
         - On PermanentError: fail immediately
         - Return RetryResult with attempt details

    6. Use `tenacity` library (already in tech stack):
       - `@retry(stop=stop_after_attempt(5), wait=wait_exponential(multiplier=1, min=1, max=16))`
       - Or implement custom logic for more control

    Per ERRO-01: Exponential backoff 1s→2s→4s→8s→16s (max 5 retries).
